# 食友 ShiYou · 后台管理系统（Vue 版原型）

> 由 `management-system/食友后台原型图.html` 整理、重构而来的 **Vue 3 实现版**。
> 目标：把原来一份 6000+ 行的单文件 HTML 原型，拆解为「模块清晰、组件可复用、代码可阅读」的
> 工程化结构，方便其他人快速理解后台系统的功能设计与页面布局。

---

## 一、快速开始

```bash
cd management-system/shiyou-admin
npm install
npm run dev        # 开发预览，默认 http://localhost:5174
npm run build      # 构建产物输出到 dist/
```

打开页面后先在「管理员登录」页点击**登录**（原型无需真实校验），即可进入后台。

## 二、目录结构

```
shiyou-admin/
├─ index.html                 # Vite 入口
├─ vite.config.js             # 构建配置（@ 别名指向 src）
├─ package.json
└─ src/
   ├─ main.js                 # 应用入口
   ├─ App.vue                 # 根组件（仅承载路由视图）
   ├─ router/index.js         # 路由表：20 个后台页面 + 登录页，含菜单标题
   ├─ assets/admin.css        # 全局样式（由原 HTML 样式整理而来）
   ├─ store/logs.js           # 操作日志中心：所有页面 CRUD 都会写入日志
   ├─ composables/            # 可复用逻辑
   │  ├─ useTable.js          #   列表页：筛选 / 分页 / 勾选
   │  ├─ useToast.js          #   全局轻提示
   │  └─ useDialog.js         #   确认弹窗
   ├─ components/             # 共享组件
   │  ├─ AdminLayout.vue      #   后台布局（侧边栏 + 顶栏）
   │  ├─ StatusTag.vue        #   状态标签（自动按文案着色）
   │  ├─ BaseButton.vue       #   按钮（primary / danger / warning...）
   │  ├─ PageHeader.vue       #   页面头（标题 + 描述 + 操作区）
   │  ├─ Pagination.vue       #   分页器
   │  ├─ AppModal.vue         #   弹窗（表单 / 详情 / 确认）
   │  └─ ToastHost.vue        #   Toast 宿主
   ├─ data/mock.js            # 原型演示数据（字段即后台数据模型）
   └─ views/                  # 20 个页面视图 + 登录页
```

**阅读顺序建议**：`router/index.js`（看模块全貌）→ `AdminLayout.vue`（看导航结构）
→ `data/mock.js`（看数据模型）→ 各 `views/*`（看具体页面）→ `store/logs.js`（看审计设计）。

## 三、模块划分（7 组 · 20 页）

| 菜单分组 | 页面 | 路由 name | 核心职责 |
| --- | --- | --- | --- |
| 首页 | 工作台 | `dashboard` | 待办统计、快捷入口、操作动态 |
| 内容审核 | 待审核凭证 | `voucherAudit` | 消费凭证审核，通过后评价显示「已验证消费」 |
| | 举报处理 | `reportAudit` | 举报成立后评价永久下架；达到阈值自动隐藏 |
| | 二次审核队列 | `secondAudit` | 低信誉用户 / 凭证多次被拒用户的评价审核 |
| | 已下架内容 | `removedContent` | 已下架评价的归档查看 |
| 用户与基础数据 | 用户管理 | `users` | 用户查询、封禁 / 解封、信誉分（不可代注销） |
| | 学校管理 | `schools` | 学校基础信息，控制校内 / 校外范围 |
| | 标签列表 | `tags` | 预设标签 / 菜品类别（前台不可自定义） |
| | 标签分组列表 | `tagGroups` | 标签分组维护 |
| 店铺管理 | 店铺列表 | `shops` | 正式店铺维护、上下线、范围控制 |
| | 待确认店铺 | `pendingShops` | 用户建店审核：确认 / 合并 / 补充 / 驳回 |
| | 合并记录 | `mergeRecords` | 待确认店铺合并历史的归档 |
| 榜单管理 | 榜单任务 | `rankingTasks` | 店铺榜 / 评论榜刷新任务（自动 + 手动） |
| | 榜单快照 | `rankingSnapshot` | 最近一次榜单计算结果，用于排查排名异常 |
| 系统管理 | 系统设置 | `settings` | 评价规则、热度权重、榜单、凭证清理 |
| | 操作日志 | `logs` | 后台关键请求审计，支持多维筛选 |
| 权限管理 | 管理员账号 | `admins` | 账号 + 角色分配（超级管理员内置不可删） |
| | 角色管理 | `roles` | 角色维护 + 菜单 / 按钮授权 |
| | 权限管理 | `permissions` | 接口权限 / 按钮权限维护 |
| | 菜单管理 | `menus` | 左侧菜单 + 路由 + 显示权限维护 |

## 四、核心数据模型（对应 mock.js）

- **凭证 `voucher`**：提交人 / 关联店铺 / 评价摘要 / 提交时间 / 状态（待审核、已超时）
- **举报 `report`**：举报人 / 被举报评价 / 原因 / 举报次数 / 状态（待处理、已自动隐藏）
- **二次审核 `secondAudit`**：用户 / 信誉分 / 触发原因（信誉分低于阈值、凭证多次被拒）/ 详细原因
- **用户 `user`**：ID / 昵称 / 手机号 / 学校 / 评价数 / 信誉分 / 状态（正常、封禁、已注销）
- **学校 `school`**：名称 / 校区 / 经纬度 / 状态
- **标签 `tag`**：名称 / 分类（口味、性价比、堂食体验、菜品类别）/ 是否榜单维度 / 排序 / 状态
- **店铺 `shop`**：名称 / 范围（校内、校外）/ 所属学校 / 类型（实体店、外卖）/ 位置 / 评价数 / 状态
- **待确认店铺 `pendingShop`**：品类 / 范围 / 位置说明 / 创建人 / 关联评价数 / 相似提示 / 状态
- **榜单任务 `rankingTask`**：任务名称 / 榜单类型（店铺榜、评论榜）/ 最近刷新时间 / 触发方式 / 状态 / 失败原因
- **榜单快照 `rankingSnapshot`**：排名 / 上榜对象 / 对象类型 / 最终分 / 热度分 / 有效评价数 / 计算时间
- **管理员 `admin`**：账号 / 角色 / 状态 / 创建时间 / 更新时间（`builtin` 标记内置账号）
- **角色 `role`**：名称 / 编码 / 定位 / 状态（`builtin` 标记内置角色）
- **权限 `permission`**：名称 / 编码（如 `voucher:audit`）/ 所属模块 / 类型（接口、按钮）/ 状态
- **菜单 `menu`**：名称 / 编码 / 父级菜单 / 路由路径 / 排序 / 状态

## 五、RBAC 权限设计（重点）

后台采用 **账号 → 角色 → 权限（菜单 + 接口/按钮）** 三级模型：

```
管理员账号 (admins) ──分配──▶ 角色 (roles) ──授权──▶ 权限 (permissions) + 菜单 (menus)
```

- **角色授权**：在「角色管理」点击「授权」，弹窗中以复选框勾选菜单与接口 / 按钮权限，
  预设值来自 `rolePermissionPresets`（内容管理员、系统管理员、用户和店铺信息管理员）。
- **内置账号 / 角色**：超级管理员（`super_admin`）为系统内置，仅可查看权限，不可删除 / 编辑。
- **权限编码规范**：`模块:操作`，如 `voucher:audit`（审核消费凭证）、`ranking:refresh`（手动刷新榜单）、
  `role:assign`（分配角色）、`admin:delete`（删除管理员）。
- **菜单权限**：菜单不仅决定左侧导航显示，同时绑定前端路由路径（`/audit`、`/ranking` 等）。

## 六、通用交互约定（各列表页统一）

1. **筛选**：关键字输入 + 下拉条件（状态 / 范围 / 分类等），回车或点击「查询」生效，「重置」恢复默认。
2. **分页**：页脚统一分页器，展示总数与当前页，每页 3~5 条。
3. **勾选**：表头全选（仅当前页），行勾选后支持「批量删除」。
4. **弹窗**：新增 / 编辑 / 详情 / 授权均通过 `AppModal` 完成；删除需二次确认。
5. **日志**：任何增删改操作都会调用 `appendLog()` 写入 `store/logs.js`，
   「操作日志」页实时可见，模拟后端审计日志。

## 七、与原 HTML 原型的关系

| 原 HTML | Vue 版 |
| --- | --- |
| 单文件 6000+ 行（HTML + CSS + JS 混写） | 20 个页面组件 + 7 个共享组件 + 组合式函数 |
| 页面切换通过 `goPage()` 显隐 `div` | Vue Router 路由切换（URL 可直达，如 `#/admin/roles`） |
| 筛选 / 分页逻辑每页手写 | `useTable` 统一封装 |
| 弹窗 HTML 拼接字符串 | `AppModal` 组件 + 具名插槽 |
| 日志写入 DOM 表格 | 全局 `logsStore` 响应式数组 |

原 HTML 文件保留在同目录（`management-system/食友后台原型图.html`），可作为设计对照参考。

## 八、演示限制说明

- 所有数据均为**静态示例数据**（`src/data/mock.js`），操作只修改前端内存，不请求后端。
